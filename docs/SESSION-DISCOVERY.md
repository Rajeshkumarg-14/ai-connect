# Discovering existing sessions

Connect reads saved session **metadata** from the current user's `.claude/projects` and `.codex/sessions` directories and checks Windows coding-agent processes. It reads a bounded header and tail of recent JSONL files, tolerates partial writes, and does not follow directory symlinks. Discovery returns project directories, provider, session ID, activity time and process evidence. It does not return conversation text, tool output, process command lines or transcript paths.

A session is marked **running** when a process has the same explicit session ID (for example `--resume`), a metadata PID matches the live process, or Claude's per-PID session registry identifies a session whose PID is alive. When process enumeration is available, registry PIDs must also match a Claude process. If enumeration is unavailable, registry evidence explicitly says process identity could not be independently checked: PID reuse remains a limitation. Only `.json` registry metadata is read; messaging keys and pipes are untouched. A recently modified transcript is marked **recent**, even if a process of the same provider exists. Interactive CLIs frequently start without a session ID in their arguments, so the Windows process list alone cannot reliably associate them with a saved conversation. Unmatched coding-agent processes are reported separately. No terminal keystrokes, undocumented pipes, or active-session resume commands are used.

An **Add Codex** action creates a separate managed partner using the selected session's project directory. This does not attach to or take over the original terminal. The partner can inspect the shared repository. Conversation context is included only if the user explicitly opts into a bounded snapshot. That excerpt can contain private information: it is labeled untrusted reference material and never confers permission or human approval. Tool output and reasoning blocks are omitted. The snapshot does not refresh automatically.

Claude Code has an official live messaging mechanism: `ListAgents` and `SendMessage`. Native Windows requires Claude Code v2.1.234 or later; local delivery uses per-session named pipes. These are tools invoked by Claude within an eligible session, rather than a documented external broker API. Connect does not emulate the private named-pipe protocol. See [official cross-session messaging documentation](https://code.claude.com/docs/en/cross-session-messaging). Connect's optional experimental managed relay uses those tools and preserves the receiving session's permissions. Native delivery must be reported successful before the UI shows connected; a provider quota, missing tool, or refused incoming message can prevent pairing. Live native relay delivery has not yet been verified in this environment because Claude usage was exhausted during testing.

Discovery checks up to 240 candidate files per provider by default (600 for explicit context lookup), up to 180 directories per provider, and returns at most 60 recent sessions. A saved session older than 30 days is excluded unless it has a verified live process match. The API includes `scope` metadata describing those bounds; a UI filter labeled **All discovered** means this bounded result set, not every historical session. Missing/inaccessible files are skipped. If metadata layouts change, a session may not appear. Refresh discovery after starting or resuming a CLI. The original terminal remains controlled by its owner.

## Reading a conversation

Clicking a discovered session authorizes a read-only transcript view through the authenticated local endpoint `GET /api/sessions/:id/transcript`. It returns the latest 50 user/assistant text messages in chronological order. **Load earlier** uses stable byte-offset cursors and prepends preceding pages without resuming, importing, or modifying the source session. The ID is resolved against known session roots; callers cannot provide a transcript path.

Each request reads at most a 4 MB transcript window. If internal records fill that window, a page can contain fewer messages; its cursor still allows continuing earlier. Individual text messages longer than 100,000 characters are clipped with a notice. Tool calls/results, reasoning, analysis-channel messages, harness system/environment blocks and known environment credential assignments are omitted. Other text in your conversation can still contain sensitive information. A malformed record or a partially written final line is ignored. Reloading fetches newly appended messages. No AI model runs or token charges are triggered by opening the transcript.
